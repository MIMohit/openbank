# E4 — malicious-but-legitimate client vs. a gateway PDP (W12)

The scenario the kill experiment (`../kill/`) did not test: a legitimate tenant `alice` who
holds a valid token + DPoP key and can mint a proof for **any** `(htm, htu)`, attacking a
**policy decision point** that authorizes by **matching the request path** against an
ownership/role policy on top of the RFC 9449 proof check. Question: can she craft a path the
PDP reads as one of her own resources but the backend routes to a forbidden resource/op?

**Answer and findings:** [`REPORT.md`](REPORT.md). Root causes + citations:
[`ROOT_CAUSES.md`](ROOT_CAUSES.md). Disclosure candidates: [`FINDINGS.csv`](FINDINGS.csv).
**7 independent G2 authorization-soundness classes, 0 G3; 2 defeat the strict allow-list.**

## Layout

| path | what |
|---|---|
| `../../harness/pdp/` | the PDP service (`bh-pdp-*` images) — see its own README |
| `cases.jsonl` | the 29-vector A_client battery (generated by `scripts/gen_cases.py`) |
| `topologies/` | 65 topology YAMLs (gw × policy × profile × framework), `scripts/make_topologies.py` |
| `scripts/e4_runner.py` | mints alice's matching proof per vector, sends raw bytes, logs `runner.jsonl` |
| `scripts/e4_oracle.py` | authorization-soundness oracle (reuses `oracle.correlate`) → `violations.jsonl`, `outcomes.csv` |
| `scripts/analyse_e4.py` | aggregates `runs/*` → `analysis/{violations_all,by_topology}.csv`, `classes.json` |
| `scripts/run_one.sh`, `sweep.sh`, `rerun_e4.sh`, `rerun_driver.sh` | up/battery/down; sweep; 3× fresh reruns |
| `scripts/e4_ddmin.py`, `ddmin_driver.sh` | ddmin a hit's request delta against a live topology |
| `scripts/run_native.sh`, `native/` | gateway-NATIVE path-ACL tests (item 2) |
| `runs/`, `reruns/`, `ddmin/`, `native/runs/`, `analysis/` | outputs |

## How to run (all from `binding/harness`, one topology up at a time)

```sh
PY=orchestrator/.venv/bin/python
# one topology end to end (up --stubs off -> battery -> down -> oracle)
bash ../experiments/e4/scripts/run_one.sh w12-allow-ngx-aspnet-def
# the full sweep over a worklist
bash ../experiments/e4/scripts/sweep.sh ../experiments/e4/worklist_main.txt
# aggregate
$PY ../experiments/e4/scripts/analyse_e4.py
# reruns (3x fresh) for the representative per class
bash ../experiments/e4/scripts/rerun_driver.sh 3
# ddmin (brings each topology up, minimises, downs)
bash ../experiments/e4/scripts/ddmin_driver.sh
# native ACLs
bash ../experiments/e4/scripts/run_native.sh w12-nat-ngx-aspnet nginx_native.conf
```
Topologies override `verifier.image` with `bh-pdp-{allow,block}[-n]:latest` and set
`host_port`. All containers/compose projects are prefixed `w12-` (CONTRACT §0).

## How to test
- PDP unit tests: `PYTHONPATH=$PWD ../verifier/.venv/bin/python -m pytest pdp/tests/ -q` (18).
- End-to-end soundness is the experiment itself; every hit is re-run 3× (`reruns/`) and the
  distinct differentials are ddmin-minimised (`ddmin/`).

## Known limitations
See [`REPORT.md`](REPORT.md) §13. In short: the matrix worklist ran 65 of the full 144 cells
(prioritising W5-lead combos; recommended-profile Express and some rails/express × gateway
cells were out of scope); the battery omits the absolute-form and `X-Original-URL`/
`X-Rewrite-URL` (G3) vectors — that probe is open, not shown-null; the PDP authorizes a single
tenant (`alice`). Never edits `gateways/` or `orchestrator/`; native configs are copies of the
renderer output under `native/configs/`.
